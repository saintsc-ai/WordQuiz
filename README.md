# 한글 워들 (WordQuiz)

한글 낱말을 **자모 단위**로 맞히는 웹 게임. 5번 안에 정답 명사를 찾으면 이깁니다.

```
안녕  →  ㅇ ㅏ ㄴ ㄴ ㅕ ㅇ   (6칸)
```

## 규칙

1. 자모 **5 · 6 · 7 · 8 · 9 · 10개** 중 길이를 고릅니다.
2. 화면의 간략화 자판으로 자모를 한 칸씩 입력합니다.
3. 자모가 모두 일치하면 승리.
4. 추측하는 단어도 **사전에 있는 명사**여야 합니다.
5. 채점
   - 🟩 자모와 자리가 모두 맞음
   - 🟨 그 자모는 들어있지만 자리가 다름
   - ⬜ 정답에 없는 자모
6. 기회는 **5번**.
7. 단어는 판마다 새로 뽑습니다. **몇 번이든 다시 풀 수 있습니다.**
8. 점수는 **한 단어당 한 번만** 등록됩니다. 한 번 등록한 단어는 다시 뽑히지 않습니다.

## 자판과 자모 분해

자판은 두벌식에서 쌍자음과 복합모음 키를 뺀 **24키**입니다.

| | 키 |
|---|---|
| 자음 14 | ㄱ ㄴ ㄷ ㄹ ㅁ ㅂ ㅅ ㅇ ㅈ ㅊ ㅋ ㅌ ㅍ ㅎ |
| 모음 10 | ㅏ ㅑ ㅓ ㅕ ㅗ ㅛ ㅜ ㅠ ㅡ ㅣ |

나머지 자모는 전부 이 24키의 조합으로 입력합니다.

| 종류 | 예 |
|---|---|
| 쌍자음 | ㄲ = ㄱㄱ, ㅆ = ㅅㅅ |
| 겹받침 | ㄺ = ㄹㄱ, ㅄ = ㅂㅅ |
| 복합모음 | ㅐ = ㅏㅣ, ㅘ = ㅗㅏ, ㅢ = ㅡㅣ |

따라서 `꽃` = ㄱㄱㅗㅊ(4), `사과` = ㅅㅏㄱㅗㅏ(5) 처럼 셉니다.
3키가 필요한 **ㅙ, ㅞ** 만 지원하지 않으며 해당 단어는 사전에서 제외됩니다.

> 자모열이 단어와 항상 1:1은 아닙니다. `ㄱㅏㄱㄱㅏ` 는 `가까` 와 `각가` 둘 다에 해당합니다.
> 사전을 자모열로 색인하므로 이런 단어는 모두 추측으로 인정됩니다.

## 링크로 공유하기

판이 끝나면 **링크 복사** 로 지금 푼 단어를 그대로 담은 주소를 얻습니다.

```
https://.../#p=sOrasf_usf3S
```

정답 단어를 UTF-8 → XOR → base64url 로 감싼 값이라 주소만 봐서는 알 수 없습니다.
암호가 아니라 눈에 띄지 않게 하는 정도입니다. 링크를 연 사람은 같은 단어를 풀게 되고,
제목이 **공유받은 단어** 로 바뀝니다. ↻ 를 누르면 무작위 새 단어로 돌아갑니다.

**결과 공유** 는 이모지 격자와 링크를 함께 내보냅니다. 모바일에서는 공유 시트가 뜹니다.

### 직접 출제

머리말의 **⋯** 에서 **직접 출제** 를 누르면 낼 단어를 직접 고를 수 있습니다. 한글로 치면
사전에 있는 명사인지, 자모가 5 ~ 10칸인지 바로 확인해 주고 링크를 만들어 줍니다.
추측 허용 목록(명사 전체)에 있으면 되므로 정답 후보보다 훨씬 넓게 낼 수 있습니다.

내가 낸 단어는 브라우저가 기억해 둡니다. 출제 링크를 복사해 스스로 다시 열어도
정답을 아는 채로 푸는 것이라 점수에 넣지 않습니다. 링크를 받은 사람은 영향이 없습니다.

### 한 단어, 한 번

점수를 등록한 단어도 같은 방식으로 기억합니다. **링크 복사** 로 얻은 주소를 스스로
다시 열어 풀면 답을 아는 채로 푸는 것이므로 등록 버튼이 잠기고, 그 단어는 이후
무작위 후보에서도 빠집니다. 서버도 `(브라우저, 단어)` 로 같은 판단을 하므로
저장소를 지워도 같은 브라우저에서는 다시 등록되지 않습니다.
링크를 받은 사람은 처음 푸는 단어이니 영향이 없습니다.

```
한글 워들 · 자모 6칸  3/5
⬜🟩🟨⬜⬜🟩
🟩🟩⬜🟨⬜🟩
🟩🟩🟩🟩🟩🟩
https://.../#p=sOrasf_usf3S
```

## 실행

의존성도 빌드 단계도 없습니다.

```bash
python -m http.server 8000
# http://localhost:8000
```

`index.html` 을 브라우저에서 직접 열어도 동작합니다. (데이터를 `fetch` 가 아니라
`<script>` 주입으로 읽기 때문)

## 화면 테마

머리말의 **☾ / ☀ / ◐** 를 누르면 **어둡게 · 밝게 · 시스템** 이 차례로 돌아갑니다.
**⋯** 안에서 직접 고를 수도 있습니다. 고르지 않으면 OS 설정을
따라가고, OS 설정이 바뀌면 새로고침 없이 따라 바뀝니다.

색은 전부 CSS 변수로만 씁니다. 토큰 이름과 팔레트, 명도 대비 기준은
[STYLE_GUIDE.md](STYLE_GUIDE.md) 에 있고 검사는 스크립트가 합니다.

```bash
python tools/check_css.py
```

## 힌트

자모 칸이 길어지면 그 길이의 명사가 잘 떠오르지 않습니다. 자판 위 **힌트** 를 누르면
그 길이의 단어를 하나 보여 줍니다. **정답도 아니고, 이미 낸 단어도 아닙니다** — 어떤
단어들이 있는지 감을 잡으라는 것뿐입니다.

값은 치릅니다. 한 번 볼 때마다

```
점수  − 자모 수
시간  + 자모 수 × 20초
```

10자모라면 한 번에 10점과 3분 20초입니다. 횟수 제한은 두지 않았습니다. 값이
쌓이니 점수는 0점에서 멈추고 시간만 늘어납니다.

## 점수 등록

닉네임을 한 번 넣어 두면 **끝난 판이 손대지 않아도 올라갑니다**. 이긴 판은 점수와 함께,
진 판은 0점으로 남습니다. 승패가 다 남아야 누적 순위의 판수와 승률이 말이 됩니다.

시계는 **첫 자모를 친 순간**부터 갑니다. 판만 띄워 두고 딴 데 봐도 시간이 늘지 않습니다.

시작한 판을 버리고 ↻ 나 다른 길이로 넘어가면 **실패로 기록**됩니다. 넘어가기 전에
물어보고, 계속 풀기를 고르면 아무것도 남지 않습니다. 마음에 안 드는 단어를 계속
넘겨 가며 쉬운 것만 고르지 못하게 하려는 것입니다.

### 스코어보드 연결

스코어보드는 Google Sheets와 Google Apps Script Web App을 선택적으로 연결할 수
있습니다. 자세한 설정은 [SCOREBOARD_SETUP.md](SCOREBOARD_SETUP.md)를 보세요.
URL을 설정하지 않으면 게임과 결과 공유만 사용할 수 있습니다.

판마다 다른 단어를 풀기 때문에 '같은 문제를 누가 잘 풀었나'를 셀 수 없습니다.
그래서 순위는 사람별로 셉니다. **오늘 순위 · 전체 순위** 를 고르고, 그 안에서
세 가지로 나눠 봅니다.

| 방식 | 무엇을 세나 |
|---|---|
| 누적 점수 | 점수 합계 (많이 · 잘 풀수록) |
| 타임어택 | 가장 빨리 푼 한 판 |
| 점수어택 | 한 판 최고 점수 |

타임어택과 점수어택은 이긴 판만 셉니다.

## 단어 데이터 다시 만들기

`data/*.js` 는 이미 커밋되어 있으므로 평소에는 실행할 필요가 없습니다.
사전을 갱신하려면:

```bash
python tools/fetch_krdict.py   # 원본 zip 내려받기 (약 84MB, data/raw/)
python tools/build_dict.py     # data/words-N.js, answers-N.js 생성
python tools/check_sync.py     # 규칙이 어긋나지 않았는지 확인
```

사전을 다시 만들었다면 `index.html` 의 `APP_VERSION` 도 올려야 브라우저가
낡은 데이터를 붙들지 않습니다.

| 자모 수 | 추측 허용 | 정답 후보 |
|---:|---:|---:|
| 5 | 4,703 | 1,165 |
| 6 | 6,996 | 1,547 |
| 7 | 3,346 | 875 |
| 8 | 4,466 | 1,012 |
| 9 | 3,856 | 817 |
| 10 | 1,578 | 385 |

- **추측 허용**: 한국어기초사전의 명사 전체 중 해당 길이인 것
- **정답 후보**: 그중 어휘등급이 초급 · 중급인 것

## 구조

```
index.html          화면 뼈대
css/style.css       다크 테마
js/theme.js         밝게 / 어둡게 (head 에서 먼저 실행)
js/store.js         localStorage (길이 · 닉네임 · 익명 ID · 출제/등록한 단어)
js/jamo.js          한글 ↔ 자판 입력열 변환
js/dict.js          단어 데이터 로딩 · 검증, 자모 길이 목록
js/game.js          게임 상태와 채점 (DOM 비의존)
js/scoreboard.js    Apps Script 스코어보드 클라이언트
js/ui-sheet.js      시트(모달) 셸 · 포커스 관리 · 토스트
js/ui-share.js      링크 만들기 · 해시 읽기 · 클립보드
js/ui-board.js      보드와 자판 렌더링
js/ui-score.js      결과 시트 · 순위 시트
js/ui-compose.js    직접 출제 시트 · 규칙 시트
js/ui.js            조립 · 입력 처리 · 해시 라우팅
tests/              브라우저에서 여는 테스트
tools/              사전 내려받기 · 가공 · 검사 스크립트
data/               생성된 단어 데이터
```

같은 규칙이 js 와 python 에 두 벌로 적혀 있습니다. `js/jamo.js` 의 `EXPAND` ·
`UNSUPPORTED` 는 `tools/build_dict.py` 의 것과, `js/dict.js` 의 `LENGTHS` 는
`tools/build_dict.py` 의 `LENGTHS` 와 항상 같아야 합니다.

```bash
python tools/check_sync.py   # 두 벌이 어긋나지 않았는지 검사
python tools/check_css.py    # 색 토큰과 명도 대비 검사
```

## 테스트

의존성 없이 브라우저에서 엽니다.

```bash
python -m http.server 8000
# http://localhost:8000/tests/
```

`js/jamo.js` 와 `js/game.js` 의 순수 로직(자모 분해, 채점, 공유 코드, 판 진행,
결과 링크 복원)을 검사합니다. DOM 을 만지지 않습니다.
